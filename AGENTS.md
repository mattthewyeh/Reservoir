# Reservoir agent instructions

- Keep booking and [availability](backend/app/routes/equipment.py) predicates aligned with the confirmed-only `[)` exclusion in [models](backend/app/models.py): use strict overlap inequalities and exclude cancelled rows. Preserve rollback and HTTP 409 translation for only `no_overlapping_confirmed_reservations` in [booking](backend/app/routes/reservations.py); the precheck cannot prevent concurrent inserts, and unrelated integrity errors must not become booking conflicts.
- Preserve cancellation's early return for already-cancelled rows before the member start-time check. Retrying cancellation must still succeed after the start time; admins may cancel started bookings. See [member](backend/app/routes/reservations.py) and [admin](backend/app/routes/admin_reservations.py) handlers.
- Use migrated PostgreSQL and independent Sessions for race tests. The [SQLite fixtures](backend/tests/conftest.py) bypass Alembic and the PostgreSQL exclusion constraint, and their client shares one Session across requests. Passing those tests (including a mocked commit failure) does not establish concurrency safety. See [PostgreSQL coverage](backend/tests/postgres/test_postgresql.py).
- Do not infer populated-database upgrade safety from the empty-database migration round trip. [Password migration](backend/migrations/versions/616fe554c15f_add_user_password_hashes.py) adds a non-null column without a backfill; [overlap migration](backend/migrations/versions/a4d7f6b2c901_prevent_overlapping_reservations.py) requires existing confirmed bookings to be non-overlapping and leaves `btree_gist` installed on downgrade. Verify existing data before applying these revisions to a populated database.
- Point `TEST_DATABASE_ADMIN_URL` only at a disposable PostgreSQL cluster: the [fixture](backend/tests/postgres/conftest.py) creates databases and force-drops them during cleanup. Clean up the `db-test` service without deleting the development `postgres_data` volume; see [test isolation](README.md#run-the-tests) and [Compose storage](compose.yaml).
- Preserve production's component-based database configuration and `URL.create` escaping in [database configuration](backend/app/database.py). A non-empty `DATABASE_URL` overrides all components; do not introduce one into production that bypasses the separately injected Secrets Manager password. See [runtime secrets](infrastructure/terraform/main.tf).
- Preserve Terraform's ECS service `ignore_changes` for `desired_count` and `task_definition`: the [deployment workflow](.github/workflows/deploy.yml) owns releases and task count. Production sets `RUN_MIGRATIONS=false`; the workflow runs the one-off migration before updating the service. Do not re-enable migrations on every production task startup. See [Terraform](infrastructure/terraform/main.tf), [entrypoint](backend/docker-entrypoint.sh), and [deployment rationale](infrastructure/README.md#bootstrap).
